# M5-4 計畫：兩層串接（FDC 警報 → 共同性分析 → 機台歸因）

> 這份計畫對應 `ROADMAP.md` 的 M5 驗收條文：
> 「把 FDC 找到的異常 wafer-step 丟進 M3 的共同性分析 → 確認能收斂到正確機台
> （**兩層串接**是本專案的關鍵驗收）」
>
> 也就是說：M5-4 不是新想法，而是**已承諾的關鍵驗收**。分段與判準必須在動手前寫死。

---

## 1. 命題

| 層級 | 分析單位 | 方法 | 已完成的產出 |
|---|---|---|---|
| 第一層（過程面） | 加工事件 | 單變量管制圖（M5-1）、MSPC（M5-2） | 事件層警報；M5-2 明細 5,293 列 |
| 第二層（共同性） | 批次（lot）／機台 | 超幾何 ≡ Fisher's exact 的共同性分析（M3） | 機台 enrichment 排名 |

**M5-4 要回答的問題**：把第一層的警報聚合起來做第二層的共同性分析，
**排名是否收斂到真正故障的機台**？

**與 M3 的差別（這才是 M5-4 的價值）**

- M3 的 TCA 輸入是**結果面**：壞批次標籤（lot outcome）。
- M5-4 的 TCA 輸入是**過程面**：FDC/MSPC 警報。
- 若兩者指向同一台機台 → **過程面可以被結果面獨立驗證**（有價值的正向結論）。
- 若指向不同 → 說明警報抓到的變異與良率/故障無關（同樣有價值的結論，且是可對外交代的洞察）。

## 2. 分段、產出與判準

### M5-4-0 前置診斷（唯讀；不成立就停手回報）

1. **可聚合性**：事件層警報 → 批次。需確認 `mart.lot_membership` 能提供
   event → lot → tool 的對應，且一個批次的事件同屬一台機台（否則聚合語意要先定義）。
2. **訊號量**：聚合後每個批次有幾個警報、有警報的批次佔比多少
   （太少 → 檢定力不足；太多 → 沒有鑑別力）。
3. **洩漏檢查（最關鍵的一條）**：
   - 允許：用**批次內**的警報推論該批次（實務上的 in-situ 監控）。
   - 禁止：使用該批次**之後**的資訊（例如後續批次的警報）。
   - 必須在程式中以測試機製化證明（比照 M5-1 的
     `test_baseline_is_not_contaminated_by_the_monitored_part`：把未來整段改動，斷言結果不變）。
4. **負控制可用性**：04M01 無故障標籤 → 必須能被當作負控制排除。

### M5-4-1 警報聚合（產出 `mart.lot_alert_features`）

每個批次一列，特徵包含：警報事件數、警報比例、共識警報數、
robust/plain 分開計數、最早警報發生在批次內的相對位置。
**覆蓋率必須揭露**（沒有被建模的集團、沒有警報的批次都要明列，不得靜默過濾）。

### M5-4-2 第二層共同性分析（FDC-TCA）

**介面已驗證可重用（這讓第二層幾乎是免費的）**：

| M3 用的 | M5-4 換成 | 重用 |
|---|---|---|
| `units`：批次是否有**不良結果**（`mart.lot_units.outcome_bad`） | `units`：批次是否有 **FDC 警報**（由 `mart.mspc_alerts` 聚合） | 同一個 `rank_groups(units, memberships, cfg)` |
| `memberships`：`mart.lot_membership` | **完全不變**（鍵已於 009 正規化） | 直接沿用 |
| 檢定與校正：`contingency_stats`／`fisher_exact_greater`／`bonferroni`／`benjamini_hochberg` | 不變 | 直接沿用 |

也就是說：**第二層只換「單位的屬性定義」，統計機器完全不動** ——
這同時是最強的一致性保證（兩層用同一套檢定，差異只可能來自輸入）。
產出：機台（以及 recipe／步驟）的 enrichment 排名與 q 值。

⚠ 但這件事有代價，必須在 M5-4-0 量測並揭露：**共因相關**（M5-1 已證實）讓
「警報」不是獨立事件 → 超幾何檢定的「單位獨立」假設會被違反 →
必須報告依賴程度（例如同一批次的警報在感測器間的一致性），
並在結論中用「一致性」而非「顯著性」當主要證據。

### M5-4-3 交叉驗證與判準（**動手前先寫死**）

| # | 判準 | 通過條件 |
|---|---|---|
| 1 | 負控制 | 04M01（零故障）**不得**進入前 2 名 |
| 2 | 命中 | 真正有故障的機台（02M02 21 次／01M02 18 次／03M01 12 次）至少一台進前 2 名 |
| 3 | 跨方法一致 | FDC-TCA 的機台排序與 M3（壞批次）／M5-2（警報率）方向一致 |
| 4 | 不通過時的措辭 | 只能說「FDC 警報未能收斂到正確機台」，並列出可能原因（警報飽和、共因相關、答案本身是批次相似性而非機台），不可寫成「已證明方法無效」 |

### M5-4-4 報告與誠實揭露

- 方法論寫進 `METHODS.md`：兩層各自的輸入、輸出、以及「過程面 vs 結果面」的差別。
- 誠實落差表補上 M5-4 專屬項：PHM 無真實良率（只有故障標籤）、無腔體 ID、無保養紀錄、
  警報為事件層而非 wafer 層。

## 3. 評估協定（防止自欺）

1. **事前定義判準**（上表），跑完才看結果，不事後調整門檻。
2. **負控制必備**：04M01（零故障）在每一個判準裡都要出現。
3. **機器化洩漏測試**：未來資訊改動 → 結果必須不變（比照 M5-1 的既有測試模式）。
4. **覆蓋率揭露**：所有被排除的批次、集團、時間段都必須列出來。
5. **措辭紀律**：統計檢定只能支持「有／沒有證據」，不能支持「證明沒有」；
   M5-3 的三次誤判（門檻錯誤、檢定力不足、單位錯誤）都出自措辭與判準的鬆散。

## 5. 已知限制（先寫，避免事後找藉口）

- PHM 公開資料**沒有真實良率**：第二層的回應變數只能用故障標籤或批次不良標籤，
  不能宣稱「良率改善」。
- **警報層級**：FDC 警報是事件層（step 層），不是 wafer 層 → 業界的 wafer-level FDC 我們做不到。
- **只有 5 台機台、故障次數 12–21 次**：機台層排名的檢定力有限，必須用負控制與跨方法一致性補強。
- **共因相關**（M5-1 已證實）：單變量警報之間高度相關 → 第一層的警報數不是獨立證據，
  這會直接影響第二層的 enrichment 檢定（需在 M5-4-0 量測並揭露）。

## 6. 可選延伸（不列入驗收，等你決定）

- **A｜批次不良預測的增量價值（∆AUC）**：以批次為單位，比較
  「只用機台身分」vs「加入 FDC/MSPC 警報特徵」的 AUC 差異（lot 隔離 + 時間外推切分），
  回答「警報對批次不良有沒有增量資訊」。這是最接近「forecasting」的一段。
- **B｜SECOM 真實良率軌**：獨立軌，用 UCI SECOM 的 pass/fail 做真實良率的建模
  （6.64% 不平衡 → 必須用平衡正確率／AUC，不用 accuracy），補上「真實良率」缺口。
  建議放在 M6（方法評估）而不是 M5-4。
