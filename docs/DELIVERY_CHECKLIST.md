# 交付前檢查表（助理端）

> 起因：M3 這一輪連續出現 9 個缺陷，**全部集中在「新程式路徑第一次交付」**。
> 這份清單是為了讓同型錯誤不再重複。每完成一個里程碑、要交付 zip 或請使用者跑指令前，
> 逐項做完才交付。沒有做到的要**在 checklist 明確寫「此步未在助理端驗證」**。

---

## 0. 事實層：使用者手上跑的是哪一版？

- [ ] 專案根目錄 `VERSION` 與 `etl/script_version.py` 的常數一致且已遞增
- [ ] 每支交付腳本 `--version` 可執行（`python etl/<script>.py --version`）
- [ ] 交付指示的**第一步**是版本確認，並寫明「版本不符＝檔案沒更新，不是程式問題」
- [ ] **從 zip 解出的副本**（不是工作目錄那份）實跑一次主流程；模擬容器 cwd（`cd etl` 之後再跑）

## 1. 執行路徑覆蓋（最常出錯的一類）

- [ ] 列出每支腳本的**所有執行路徑**，並逐一證明「被執行過」：
  - DB 模式 vs CSV／dry-run 模式
  - append（多機台）vs 首次載入
  - `--reset`／`--reload-loaded` 等所有新旗標
  - 錯誤路徑（缺欄位、缺檔案、找不到資料）
- [ ] 沒有資料庫時用**假物件**（fake psycopg，實作 `connect/cursor/execute/fetchall/copy/write_row`）
      跑出真實結果（exit code、COPY 列數、INSERT 參數），不是只讀程式碼「看起來對」
- [ ] 錯誤路徑用假物件餵錯誤情境，確認會**在寫入任何資料前**中止並印出可操作的訊息

## 2. 參數與環境語意

- [ ] 所有參數用**使用者 shell 會產生的形式**實跑：PowerShell 會把 `01,02,04,06` 轉成 `1,2,4,6`
      （前導零消失）→ 清單類參數一律零填充並容忍多種分隔
- [ ] 路徑假設檢查：Windows/WSL 掛載、容器 cwd、bind mount 是否涵蓋新目錄
      （`analysis/`、`reports/` 這種新目錄沒掛進容器就會「程式找不到」或「報告消失」）
- [ ] **改了 `requirements.txt`／`Dockerfile` → 交付指示必須含 `docker compose build etl`**
      （`up -d --force-recreate` 只重建容器，不會重建 image）

## 3. Schema 與程式的語意一致性

- [ ] 新增／修改 migration 後，逐一核對「程式會不會寫 NULL／空字串」與欄位限制
      （PK 欄位隱含 NOT NULL，**不能** `DROP NOT NULL`；負控制之類「沒有值」的情況用哨兵值）
- [ ] 欄位名跨檔案比對（SQL ↔ Python COPY 清單）**逐欄逐序**用腳本比對，不人工抄寫
- [ ] **已套用的 migration 不改內容**；修復一律新增版本檔，且要冪等 + 結尾自檢
- [ ] 語法驗證（`pglast`）**不等於**行為驗證：catalog 語意（PK/NOT NULL/權限）無法由此得知

## 3.5 報表的「安靜過濾」

- [ ] 任何**過濾/排除**都要在輸出中看得見（數量 + 原因），尤其是 `testable` 這類門檻
      ——實測踩過：門檻把「零故障機台的專屬批次群組」安靜地濾掉，
      而那正是最關鍵的負控制證據（正確輸出應為「未列入檢定：k_bad 0 < 3（零壞批次）」）
- [ ] 對照組／負控制必須能在**預設輸出**裡被找到，不需要額外查詢或口頭解釋

## 4. 可重現性

- [ ] 所有指標用**相同 seed 跑兩次**比對；排序相關的指標（名次）改用順序無關定義
      （`rank_min = 1 + #{p 嚴格小於}`、`rank_max = #{p ≤}`、並列數）
- [ ] 交付的「預期值」來自這兩次執行，並寫明「若不一致代表什麼」

## 5. 工具紀律

- [ ] 修改檔案用的批次替換**每個都要斷言命中次數**（`assert count == 1`），避免靜默失效
- [ ] 改完立刻 `py_compile`／`ast.parse` 全部受影響檔案，並 `import` 一次
- [ ] 修完一個缺陷 → **同型掃描**：還有哪些地方是同一類（必填參數、全域表、nargs、image 層）

## 6. 交付包與公開內容

- [ ] 乾淨目錄解壓 → `git init → add → commit` 實跑；核對檔案數與總大小
- [ ] 掃描：機密樣式、**本機絕對路徑**、資料檔（`.csv/.zip/.pkl`）、單檔 > 100 MB
- [ ] `docker-compose.yml` 用 `pyyaml` 解析、SQL 用 `pglast` 解析、所有 Python 可 import
- [ ] 交付解壓指示寫明「解壓到**上一層**」（zip 內層已含專案資料夾）

## 7. 收尾：把教訓寫回去

- [ ] 新發現的陷阱寫進 `yield-commonality-analysis` skill 的 Pitfalls（含「怎麼驗」而不只是「會壞」）
- [ ] 對應症狀加進本里程碑 checklist 的疑難排解表
