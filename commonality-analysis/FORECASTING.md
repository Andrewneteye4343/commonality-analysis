# Forecasting 設計（時序預測模組）

專案的第二個核心能力：**從時序資料做預測**，而不只是「事後找根因」。
這對應到智慧製造的三種真實任務：**機台故障預測（PdM）**、**虛擬量測（VM）**、**良率預測**。

---

## 1. 三個預測任務（都要做，且都有 ground truth）

| 任務 | 形式 | 資料來源 | Ground truth | 對應職缺場景 |
|---|---|---|---|---|
| **F1 機台故障 / TTF 預測** | 回歸（剩餘時間） | PHM 2018 真實感測時序 | **官方 groundtruth TTF + 官方評分規則** | FDC 提早告警、安排 PM（預防保養） |
| **F2 虛擬量測 VM** | 回歸（預測量測值） | PHM 感測特徵 + 合成 WAT | 真實 WAT／合成 WAT 真值 | 減少量測、全檢不可能的站 |
| **F3 良率預測** | 回歸／分類（lot/wafer 良率） | 合成資料（genealogy + WAT + 感測特徵） | 合成資料的真實良率 | yield excursion 預警 |

**F1 是本專案最有說服力的一環**：PHM 2018 就是預測三種故障的 TTF，官方有評分公式：

```
subscore = exp(-0.001·GT)·|GT - SUB|      （GT 與 SUB 皆有值）
         = exp(-0.001·SUB)·SUB             （GT 為 NaN，不該發生故障時卻預測）
         = exp(-0.001·GT)·GT               （GT 有值卻沒預測 → 懲罰最重）
         = 0                               （兩者皆 NaN，正確地不預測）
→ 分數越低越好
```

我們會**直接實作這個評分函式**，與公開競賽的基準線比較——這比自訂指標更具公信力。

## 2. 預測方法階梯（由簡到繁，逐一比較）

**第 0 層：基準線（一定要先做）**
- 持續法（persistence）、歷史平均法、固定時距法
- **沒有基準線的預測結果沒有意義**——這是最常被忽略的一步

**第 1 層：古典時序**
- ARIMA / SARIMA、**指數平滑 ETS**、狀態空間模型
- 適合：單一感測器、平穩或差分後平穩、短期

**第 2 層：統計／機器學習（實務主力）**
- **梯度提升（LightGBM/XGBoost）+ lag features**：滾動統計（過去 N 步的 mean/std/min/max/slope）、
  差異值、EWMA、時間特徵（runnum、使用壽命、距上次保養時間）
- 優點：可處理多感測器與類別特徵、訓練快、對非平穩相對穩健
- 這是「**在真實 fab 最容易落地**」的做法，面試時要講得出來

**第 3 層：深度學習**
- LSTM / GRU、TCN（時序卷積）、Transformer-based、N-BEATS
- 適合：長序列、多感測器、需要自動學特徵；缺點是資料量與調參成本
- 本專案限制：**無 GPU**，用 Colab 或降低模型規模（與 WM-811K 專案相同的策略）

**第 4 層：機率式預測（進階但面試很加分）**
- Quantile regression、**conformal prediction（預測區間含覆蓋率保證）**、
  貝氏結構時序（BSTS）、MC dropout
- 為什麼重要：產線要的是「什麼時候可能壞、有多確定」，單點預測不夠 → 要給**預測區間**

---

## 3. 驗證策略（最容易被忽略、也最容易被面試官抓）

1. **Walk-forward / rolling-origin 驗證**：用過去預測未來，逐步往前滾動
2. **絕不使用未來資訊**：滾動統計只能用 `t` 之前的資料（PHM 官方也明文要求）
3. **時間切分，不可隨機切分**（與 WM-811K 的 lot 隔離同一精神）
4. **按機台分層評估**：不能只看整體平均，某些機台可能是重災區
5. **加入負控制**：對沒有故障的期間做預測，檢查誤報率

---

## 4. 評估指標

| 指標 | 用途 | 備註 |
|---|---|---|
| MAE / RMSE | TTF、VM、良率的單點誤差 | RMSE 對大誤差敏感 |
| MAPE | 相對誤差 | 數值接近 0 時會爆掉 → 慎用 |
| **官方 PHM 評分** | F1 任務 | 越低越好，直接與競賽基準比較 |
| **Pinball loss / quantile loss** | 機率式預測 | 評估預測區間品質 |
| **Coverage（覆蓋率）** | 預測區間是否可信 | 例：90% 區間應涵蓋約 90% 實際值 |
| Precision / Recall / F1 | 故障「是否會發生」的分類版本 | 稀有事件 → 看 PR 曲線不看 ROC |
| **領先時間（lead time）** | 提早多久告警 | 產線最在意：能不能排 PM |
| 誤報率 | 假警報比例 | 假警報太多，工程師就不信系統 |

## 5. 常見坑

| 坑 | 說明 |
|---|---|
| 資料洩漏 | 用未來資料做特徵、用目標的同期統計、用全期平均做正規化 |
| 累積／計數型目標 | PHM 的 `ETCHSOURCEUSAGE`、`ACTUALSTEPDURATION` 等欄位與 TTF 高度相關，用它們可能「作弊」——要明確標示哪些特徵合法 |
| 非平穩與 regime shift | recipe 版本變更、機台保養後行為改變 → 需以時間或事件分層 |
| 極端不平衡 | 故障樣本極少（PHM 82M 列中僅 1,236 筆異常）→ 不能只看 accuracy |
| 多步預測誤差累積 | 遞迴預測會放大誤差 → 用直接多步（direct multi-step）或序列到序列 |
| 只看單點預測 | 沒有預測區間就無法判斷信心 → 產線不敢用 |
| 排行榜過擬合 | 反覆用測試集調參 → 要用驗證集調參、測試集只跑一次 |

## 6. 對應里程碑

- **M7｜Forecasting 基礎**：基準線 + 古典方法 + LightGBM lag features（F1 機台 TTF，含官方評分）
- **M8｜Forecasting 進階**：DL 模型、機率式預測與預測區間、F2 VM 與 F3 良率預測
- **M9｜整合與儀表板**：把預測曲線與預測區間做進儀表板（告警 + 領先時間顯示）
